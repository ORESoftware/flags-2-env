# Reviewed prebuilt artifacts

This directory separates reviewed release artifacts from generated `build/` intermediates.

At this stage it contains only the target policy and manifest schema. No existing file under `build/` is implicitly certified or copied here. The first artifact-producing change must generate the complete manifest, prove source-input and ABI parity, perform independent rebuild comparison, run native/emulated consumer tests, and remove/ignore the legacy tracked `build/` directory atomically.

- `targets.json`: target tiers, named fixture owners, runtime floors, artifact kinds, and repository budgets.
- `manifest.schema.json`: fail-closed metadata required for each released artifact.
- `manifest.json`: intentionally absent until generated by the pinned build harness.

The schema and stdlib validator jointly require a complete Tier-1 matrix: one static and one shared library for every Tier-1 target. They also bind each artifact's target to its directory, filename, runtime floor, SDK/sysroot, byte count, SHA-256 digest, ABI/export digest, and shared-library SONAME or install name. Optional metadata is omitted when absent rather than serialized as `null`.

Active build targets use Rust/LLVM-style triples. Deferred target identifiers use a slightly broader canonical grammar so identifiers such as `wasm32-wasip1` can remain explicitly deferred without being mistaken for a host/build triple.

When `manifest.json` exists, validation reads every referenced artifact and fails on a missing file, symlink, target/path mismatch, duplicate target/kind, incomplete Tier-1 matrix, byte-size or digest mismatch, invalid static/shared metadata, or tree-budget overrun.

Validate the current contract with:

```sh
python3 scripts/validate-prebuilt-contract.py
```

An independent positive/adversarial harness is maintained in [`flags-2-env-test/feature-matrix#3`](https://github.com/flags-2-env-test/feature-matrix/pull/3). Its fixture bytes test manifest behavior only; native ABI, runtime, reproducibility, and signing certification remain later release gates.
